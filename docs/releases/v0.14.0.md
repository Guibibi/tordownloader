Prometheus metrics, a free-disk-space check, a TorBox account check at startup, nzb360 support,
and a batch of fixes that stop good releases from being failed and blocklisted.

## Upgrade notes

- **New free-space reserve, 10 GB by default.** A download now starts only when the disk has room
  for what it still has to write, plus what running downloads still need, plus 10 GB. On a share
  with less free space than that, downloads wait (they are not failed) until space frees up. To
  change it, set `download.min_free_space` in `config.yaml`: `0` only requires that the download
  fits, `-1` turns the check off.
- Torrents are now always submitted with seeding disabled, whatever your TorBox account setting
  is.
- No configuration changes are required otherwise.

## New

- **Prometheus metrics** at `http://<host>:6500/metrics`: torrents by state, TorBox slots in use,
  download speeds, free disk space, and counters for failures (by reason: stall, slow, timeout,
  rejected, …), retries, bytes downloaded, TorBox API responses and Sonarr/Radarr push-backs.
- **Free-disk-space check** (see upgrade notes). A waiting torrent shows "waiting for disk space"
  on the dashboard.
- **TorBox account check at startup.** A rejected API key, an expired or soon-expiring
  subscription, an account cooldown, or a slot count that doesn't match your plan is reported in
  the log.
- **nzb360 and the qBittorrent WebUI** now show the torrent list (`sync/maindata` is
  implemented).

## Fixed

- An outage or an expired API key no longer fails every queued torrent (which then got
  blocklisted in Sonarr/Radarr). Those errors now leave torrents queued.
- A failed local download (CDN hiccup, rate-limited link, full disk) is retried with backoff
  instead of failing the release.
- A torrent deleted on TorBox's side is detected instead of holding a slot forever.
- Sonarr/Radarr's "Remove Completed" now removes finished downloads.
- A fetch that took a while to find peers could be failed as "too slow" right after it started.
- A long rate-limit wait from TorBox no longer stalls the app for hours, and a submission TorBox
  queued no longer burns through the hourly quota.
- Re-grabbing a release that previously failed now queues it again.
- Downloads go into the release's real top-level folder, and unsafe file paths in a release are
  rejected.
- Shutdown waits for in-flight work before closing the database.
